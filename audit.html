7. Temuan prioritas + rekomendasi

P0 A. Kredensial DB beredar di chat + diminta masuk HTML

Risiko: kebocoran service_role = akses penuh DB. Aksi: rotate password, simpan di env saja, jangan tulis nilai ke HTML/laporan (laporan ini sudah disensor).

P0 B. Mode DB = memory (Supabase tidak tersambung)

Penyebab: .env tidak memuat SUPABASE_URL/SUPABASE_SERVICE_ROLE_KEY (hanya DATABASE_URL yang tak dibaca kode). Dampak: seluruh transaksi/CRUD hilang saat restart. Aksi: isi 2 env server + 2 env public anon sesuai MEMORY.md §7, jalankan db/schema.sql sekali di SQL Editor, restart, verifikasi health.

P1 C. Double-redirect login untuk kasir

Lokasi: src/app/login/page.tsx:47–49. Aksi: ganti router.replace("/admin") dengan redirect berbasis role (roleRedirect/nilai dari API).

P1 D. ID transaksi berpotensi kolisi

Lokasi: src/lib/db.ts:301 (acak 100–999). Aksi: sertakan jam-menit-detik + random, atau cek keunikan sebelum insert.

P2 E. Pembersihan kecil

Hapus DATABASE_URL yang menganggur bila tak dipakai; pertimbangkan rate-limit & bcrypt untuk login produksi; tambah try/catch → 500 + pesan di semua handler Supabase (sebagian sudah ada di helper handle()).
